The Radar score (0–100) ranks bounties by how promising they look for a contributor today. Four transparent parts:

• Reward — the money, log-scaled so mid-size bounties still register.
• Maintainer attention — recently touched issues are far more likely to get reviewed and paid.
• Repo merges work — whether the repository actually merges pull requests, how fast, and from how many different people. A repo that merged nothing in a year scores zero here, however attractive the issue looks.
• Low competition — driven by the pull requests that already reference the issue, falling back to the comment count where we have no PR data.
• Stack fit — starter-friendly flag and language. Small on purpose: your stack now filters the board rather than nudging the ranking, because a tenth of the score never moved anything.

Minus the trap penalty (up to 38). Some bounties look ideal — high value, “good first issue”, an hour of work — and are anything but: contributor after contributor opens a pull request, none is ever merged, and the bounty stays listed because nothing ever closes the issue. The comment count doesn't catch this; linked PRs do. So an issue with unmerged PRs stacked up loses points, hard, and one carrying two contradictory bounty labels loses a few more.

Tap any score ring to see the arithmetic for that bounty.

It's a heuristic to aid discovery, not advice — always read the issue, and its open PRs, before reserving.
